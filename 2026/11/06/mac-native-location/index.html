修改 Mac 本机系统定位（Core Location 模拟定位）

发表于2026-11-06|更新于2026-11-09|工具
|总字数:1.8k|阅读时长:5分钟|浏览量:

本文整理一种修改 Mac 本机系统定位的方法：通过 _locationd 的 current-host 模拟参数，让 Core Location 报告指定的经纬度，并在正常重启后生效。它不依赖 WLoc、HTTPS 代理或常驻进程，也说明了如何检查、恢复首次配置，以及彻底结束模拟、回到真实位置。

适用范围

适用：

  • 把 Mac 本机的系统定位改到某个城市（例如让天气、地图的”我的位置”显示目标地点）
  • 检查当前是否处于模拟定位
  • 恢复首次配置，或结束模拟、恢复真实定位

不适用：

  • 连接到 Mac 的 iPhone 的定位
  • 只改浏览器里的网页定位
  • VPN 出口地区（那是 IP 归属，不是系统定位）

⚠️ 这里用到的是非公开参数，不同 macOS 版本、构建的行为可能不同。在一台机器、一个版本上成功，不代表通用。换系统版本前先做兼容性检查。

原理

方法只做一件事：保存 _locationd 的模拟定位参数（current-host 域，共涉及两个域、六个参数）。脚本本身：

  • 不杀死、不重启任何系统服务
  • 不发送刷新通知、不安装登录项、不定时轮询
  • 不会自动重启电脑

参数写入后，要等下一次正常重启才会被系统读取并生效。恢复、结束模拟同理，都要重启后才算数。

状态和备份保存在 /var/db/mac-location-lab。首次的原始备份会一直保留，无论之后设置、回滚还是恢复多少次。

先分清你要做哪件事

你想要 做法 注意
只检查 当前定位 打开天气的”我的位置”或地图的当前位置按钮查看 不要改参数。保存的参数、搜索城市的结果都不能证明实际定位已经改变
设置 / 换城市 用目标点的 WGS84 经纬度执行 set 只有城市名时，先核实一个确实位于该城市的代表点
恢复首次配置 reset 首次配置本身可能就是另一个模拟位置，不等于真实位置
结束模拟、回到真实位置 disable 会先备份，再清除两个域的全部六个模拟参数

结束模拟时，不能只删其中某一项参数，也不能把坐标设成 0 来”关掉”。先用 status 看一下原始参数，免得把”恢复旧模拟”误当成”恢复真实位置”。

坐标示例：洛杉矶市中心 34.053345, -118.242349。这只是示例，不要拿它当所有请求的默认值。

操作步骤

下面的 PYTHON、SKILL_DIR、OUTPUT_DIR 都要换成本机的实际绝对路径：OUTPUT_DIR 是本次操作的结果目录。

本文只整理方法与流程，scripts/mac_location.py（核心脚本）和 scripts/request_admin.py（管理员认证包装）没有随本文发布。

1. 准备一个能用的 Python（3.9+）

/usr/bin/python3 可能因为还没接受 Xcode 许可而无法启动。这种情况换用其他已安装的 Python 3.9+，不要替自己（或别人）随手接受许可，先弄清楚再决定。

2. 体检：记录系统信息

记下输出里的 OS 构建、架构和 boot_marker（重启标记），后面用它确认是否真的重启过。

3. 如果装过 WLoc 或其他定位工具

先判断它是否需要暂停，并保留好它的恢复信息。只处理和这次任务相关的部分，不要顺手清理别的东西。

4. 以管理员身份执行操作

写入系统参数需要管理员权限。request_admin.py 会弹出系统自带的认证窗口，密码只在系统窗口里输入，不会进入命令行历史或日志。也可以自己在终端里用 sudo 直接调用核心脚本。

怎么看返回结果：

  • success: true 加上阶段 pending-reboot，只代表参数已保存并读回核对成功，还没生效。
  • 状态一直是 running：去看这次请求的 result.json 和 admin.log，不要重复提交写入。
  • 认证被取消、偏好访问被拒、回滚没有核对通过：记下具体卡在哪个阶段，保留备份。不要为了硬推进而关闭 SIP 或放大系统权限。

5. 万一中途出错或被强行中断

每次写入前都会先保存一份 pending.json：

  • 普通错误、可捕获的中断：脚本会尝试自动回滚并核对。
  • 进程被强行结束：先用 status 查看未完成的操作，确认旧进程已经退出，再用 recover 恢复到这次操作之前的参数。
  • 不能在一个未完成的操作上再叠加新的 set / reset / disable。

最近一次操作前的快照和首次备份都会保留。恢复之后，同样要正常重启并实测。

重启与验证（最关键的一步）

  1. 参数保存并核对成功后，先保存手头工作，再通过苹果菜单 → 重新启动正常重启。
  2. 重启完成后再跑一次 doctor，对比 boot_marker，确认确实发生了重启。
  3. 打开天气，看 “我的位置 / My Location”，必要时用”显示 → 前往当前位置”刷新；或者打开地图，点当前位置按钮。
  4. 看显示的城市是否和目标坐标相符。可能会显示到具体街区名，先查一下这个街区属于哪个城市，别因为名字粒度不同就判定失败。
  5. 如果你在用动态壁纸，顺便确认壁纸仍是”动态”，并看当前画面的日照是否符合目标地点的时间。不要为了”看起来对”而手动换成静态夜景。

只有当天气或地图真的显示了目标位置，才算生效。 读到了参数、”已经重启过了”、脚本退出码为 0，都不能证明定位成功。

恢复时也一样，要区分两件事：”原参数已经恢复”和”重启后真实位置已经恢复”。原参数可能本来就是一个旧的模拟配置，恢复它不等于回到了真实地理位置。

已知限制

  • 固定坐标一旦正常重启生效，就不再需要 WLoc 或任何常驻的 Python 进程。
  • 断网不会删除本地参数，但”断网后定位是否仍正确”尚未测试，不能当作已验证。另外天气刷新、地图下载本身都需要网络。
  • 每次换城市、结束模拟，都需要再正常重启一次。
  • 这是非公开参数，macOS 更新后可能失效。
  • 按 IP、独立信号或自有规则定位的 App，不一定跟随系统的 Core Location。
